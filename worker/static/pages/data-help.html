Choose a Download #

Data files are hosted in GitHub Releases. Each dataset's release lists the available files, source information and reuse terms.

  • Vector features: find a dataset in the vector catalog. In its map viewer, open Downloads, choose the source and use Partial Download to export the current map extent. Formats include GeoPackage, GeoJSON, GeoParquet, FlatGeobuf, CSV and Shapefile.
  • Full datasets: use the release or full-download links. Large datasets may have several files; see Partitioned Data.
  • Raster maps and elevation: browse the STAC collections for individual GeoTIFF sheets, or extract an area with the CLI.

PMTiles and PNG/WebP tiles are for map display. Use the feature downloads for vector analysis and GeoTIFF assets for imagery or elevation values. A STAC GeoParquet index contains sheet metadata and links, not image pixels.

Browser extraction uses your device's memory and temporary storage. Start with a small area; use the CLI for larger jobs. Geographic selection retains whole intersecting vector features rather than cutting them at the selection boundary.

GeoParquet Format #

Vector source downloads are available as GeoParquet. Many use GeoParquet 1.1 with WKB (Well-Known Binary) geometry and a per-feature bounding box column. Parquet statistics for those columns let compatible readers skip row groups outside an area of interest. Raster downloads use GeoTIFF; available formats vary by dataset.

💡 Bbox Column Filtering

GeoParquet 1.1 supports optional bounding box covering metadata. Our prepared vector files commonly use a bbox struct with xmin, ymin, xmax and ymax fields. Check the file schema before using the SQL examples below. Remote reads can still transfer large row groups; the savings depend on the file layout and the reader.

Why GeoParquet?

  • Efficient compression - Files are significantly smaller than equivalent Shapefiles or GeoJSON
  • Fast querying - Columnar format allows reading only needed columns
  • Cloud-native - Supports partial reads without downloading entire files
  • Row group skipping - Bbox columns enable spatial filtering at the Parquet level
  • Rich type support - Preserves data types accurately

Tools for Viewing GeoParquet

QGIS

Free and open-source desktop GIS. Use a QGIS build with the GDAL Parquet driver enabled; GDAL 3.9 or newer supports GeoParquet 1.1. Driver availability depends on the QGIS installation.

Simply drag and drop the .parquet file into QGIS or use Layer → Add Layer → Add Vector Layer.

DuckDB

Fast analytical database with GeoParquet support. Requires the spatial extension.

INSTALL spatial;
LOAD spatial;

-- Read file
SELECT * FROM 'file.parquet' LIMIT 10;

-- Filter by bounding box (bbox columns enable row group skipping)
SELECT * FROM 'file.parquet'
WHERE bbox.xmin <= 77.7 AND bbox.xmax >= 77.5
  AND bbox.ymin <= 13.1 AND bbox.ymax >= 12.9
  AND ST_Intersects(geometry, ST_MakeEnvelope(77.5, 12.9, 77.7, 13.1));

-- Same approach works on remote URLs (skips row groups outside bbox)
SELECT * FROM 'https://example.com/data.parquet'
WHERE bbox.xmin <= 77.7 AND bbox.xmax >= 77.5
  AND bbox.ymin <= 13.1 AND bbox.ymax >= 12.9
  AND ST_Intersects(geometry, ST_MakeEnvelope(77.5, 12.9, 77.7, 13.1));

The bbox.* column filters let DuckDB skip entire row groups via Parquet column statistics, then ST_Intersects does precise geometry filtering on surviving rows.

GeoPandas (Python)

Python library for working with geospatial data. Use GeoPandas 1.0 or newer with PyArrow for the bbox examples. The file must contain supported bounding box covering metadata.

import geopandas as gpd
from shapely.geometry import box

# Read file
gdf = gpd.read_parquet('file.parquet')

# Filter by bounding box
bbox = (77.5, 12.9, 77.7, 13.1)
gdf = gpd.read_parquet('file.parquet', bbox=bbox)

# Read from remote URL with bbox filter
gdf = gpd.read_parquet('https://example.com/data.parquet', bbox=bbox)

# Optional: exact intersection after bounding box filtering
gdf = gdf[gdf.intersects(box(*bbox))]

Bounds use the file's coordinate reference system. These examples assume WGS84 longitude/latitude. Bbox filtering selects candidate features; the optional intersection check removes features whose bounding boxes overlap but whose geometry does not.

Converting to Other Formats

Using ogr2ogr (GDAL)

Command-line tool for converting between geospatial formats. Use GDAL 3.9+ for GeoParquet 1.1 and a build with the Parquet driver. Check with ogrinfo --format Parquet.

# Convert to GeoJSON
ogr2ogr -f GeoJSON output.geojson input.parquet

# Convert to Shapefile
ogr2ogr -f "ESRI Shapefile" output.shp input.parquet

# Convert to GeoPackage
ogr2ogr -f GPKG output.gpkg input.parquet

# Convert to FlatGeobuf
ogr2ogr -f FlatGeobuf output.fgb input.parquet

# Read from remote URL using /vsicurl/
ogr2ogr -f GPKG output.gpkg /vsicurl/https://example.com/data.parquet

# Select intersecting features from a remote file
ogr2ogr -f GPKG output.gpkg /vsicurl/https://example.com/data.parquet \
  -spat 77.5 12.9 77.7 13.1

ogr2ogr Documentation → · GDAL Parquet driver requirements →

Using gdal vector (GDAL 3.11+)

Modern command-line interface for GDAL vector operations.

# Convert to GeoJSON
gdal vector convert input.parquet output.geojson

# Convert to GeoPackage
gdal vector convert input.parquet output.gpkg

# Convert to Shapefile
gdal vector convert -f "ESRI Shapefile" input.parquet output.shp

# Read from remote URL
gdal vector convert /vsicurl/https://example.com/data.parquet output.gpkg

# Filter by bounding box
gdal vector filter --bbox=77.5,12.9,77.7,13.1 input.parquet output.parquet

# Pipeline: filter remote file and convert to GeoJSON
gdal vector pipeline \
  "read /vsicurl/https://example.com/data.parquet ! \
   filter --bbox=77.5,12.9,77.7,13.1 ! \
   write --format=GeoJSON output.geojson"

import geopandas as gpd

Using geoparquet-io

A dedicated tool for GeoParquet conversions with CLI and Python API support. Works with local files and remote URLs.

# Install
pip install geoparquet-io

# CLI: Convert to various formats
gpio convert input.parquet output.geojson
gpio convert input.parquet output.shp
gpio convert input.parquet output.gpkg
gpio convert input.parquet output.fgb

# Extract by bounding box from remote URL
gpio extract https://example.com/data.parquet local.parquet --bbox "77.5,12.9,77.7,13.1"

# Extract bbox and pipe to convert in one command
gpio extract https://example.com/data.parquet --bbox "77.5,12.9,77.7,13.1" | \
gpio convert - output.geojson

# Python API
import geoparquet_io as gpio
gpio.read('input.parquet').to_geojson('output.geojson')

Or run using uv:
uvx --from geoparquet-io gpio convert input.parquet output.geojson

Using iomaps CLI

Our Python package iomaps can extract and convert data with spatial filtering. Use iomaps cli sources to list available sources and pick one for extraction:

# Install
pip install iomaps

# List sources and find candidates covering an area
iomaps cli sources
iomaps cli search --bounds "77.5,12.9,77.7,13.1"

# Use a source route returned by the catalog
iomaps cli extract -s /states/soi/ -o states.gpkg -b "77.5,12.9,77.7,13.1"

Or run using uv (no install required):

uvx iomaps cli sources
uvx iomaps cli extract -s /states/soi/ -o states.gpkg -b "77.5,12.9,77.7,13.1"

Bounds are WGS84 west,south,east,north. Coverage search finds approximate candidates; extraction checks the actual feature geometries. Use --filter-file area.geojson instead of -b for a polygon selection. Matching features retain their full geometry.

Replace https://example.com/... in the examples above with a release asset URL. See the iomaps command documentation for output formats and selection options.

Partitioned Data #

Some large datasets are split into multiple partition files for easier handling. Partitions group features spatially, but their bounding boxes can overlap.

💡 Recommended: Use iomaps CLI

Partition metadata is stored in a <base_name>.parquet.meta.json file next to the partitions. This file contains the spatial extents of each partition and the schema of the data.

The browser download tool and iomaps use this metadata to choose intersecting partitions and read matching data. Use the source route with the same extraction command as for a single-file dataset.

See Using iomaps CLI for commands.

Manual Extraction from Partitions

If you want to extract only portions you're interested in manually, you can apply spatial filters on each remote partition and merge the resulting filtered files:

# Filter each partition individually
ogr2ogr -f GPKG filtered1.gpkg /vsicurl/https://example.com/part1.parquet -spat 77.5 12.9 77.7 13.1
ogr2ogr -f GPKG filtered2.gpkg /vsicurl/https://example.com/part2.parquet -spat 77.5 12.9 77.7 13.1

# Then merge the filtered results
ogr2ogr -f GPKG merged.gpkg filtered1.gpkg -nln features
ogr2ogr -f GPKG -update -append merged.gpkg filtered2.gpkg -nln features

Merging Full Partitions

If you need the complete dataset, download the partitions and merge them. The inputs must have compatible schemas and the same CRS. The Python example loads every partition into memory:

# Using ogr2ogr
ogr2ogr -f GPKG merged.gpkg part1.parquet -nln features
ogr2ogr -f GPKG -update -append merged.gpkg part2.parquet -nln features
ogr2ogr -f GPKG -update -append merged.gpkg part3.parquet -nln features

# Using Python
import geopandas as gpd
import pandas as pd

files = ['part1.parquet', 'part2.parquet', 'part3.parquet']
gdfs = [gpd.read_parquet(f) for f in files]
merged = gpd.GeoDataFrame(pd.concat(gdfs, ignore_index=True), crs=gdfs[0].crs)
merged.to_parquet('merged.parquet')

Raster Maps and Elevation #

The STAC viewer lists map collections and sheet footprints. Item assets link to GeoTIFFs and, where available, original scans. Collections can exist without a PMTiles mosaic or a View Map entry in the raster tile list.

Use iomaps cli stac to find sheets and extract an area. It reads the published indexes and rasters directly from GitHub Releases:

# List collections and search for sheets
iomaps cli stac collections
iomaps cli stac search -c india-topo-50k -b "77.6,13.1,77.61,13.11"

# Crop matching sheets into a Cloud-Optimized GeoTIFF
iomaps cli stac extract -c india-topo-50k \
  -b "77.6,13.1,77.61,13.11" -o bengaluru.tif

Raster extraction needs gdalwarp on PATH with the COG driver available. Bounds use WGS84 west,south,east,north; the output defaults to the source CRS and resolution. Use --crs and --resolution to change them. Elevation data retains its numeric values.

After collections are updated, run iomaps cli stac --refresh collections to refresh discovery metadata. A sheet's recorded date may describe publication or indexing rather than the survey date; check its collection description.
